# Changelog

All notable changes to this project are documented in this file.

## [4.0.0] - unreleased

### Security

- **Path traversal**: queue names are validated against a strict pattern before they are used.
  - Allowed: lowercase letters, digits, `_`, `-`, and `.` (a period must be followed by another character).
  - Names must start with a letter or digit and are limited to 128 characters.
  - The filesystem persistence additionally verifies that every path stays inside `Persist:RootPath`.
- **Authentication runs first**: the basic authentication middleware now runs before OpenAPI/Scalar, routing, long polling (hash code middleware) and the controllers.
  - Anonymous requests can no longer create queues or hold long-polling connections.
  - When authentication is enabled, `/info`, the OpenAPI document and the Scalar UI also require credentials. Only `/health` and `/alive` stay anonymous.
- **Roles**: clients can have the roles `read`, `write` or `admin` (hierarchical).
  - Clients without roles get `admin` (backward compatible).
  - Insufficient roles return `403`.
- **Hardened basic authentication**:
  - Invalid Base64/UTF-8 headers return `401` instead of `500`.
  - Secrets are compared in constant time.
  - Clients are loaded once at startup.
  - Secrets can be stored as SHA-256 hash (`"Secret": "sha256:<hex>"`).
  - Invalid client configurations stop the startup.
- **Mutating endpoints no longer accept `GET`**:
  - `dequeue` and `confirmdequeue` use `POST`.
  - `remove` and `deletemessage` use `DELETE`.
  - `register` uses `PUT`.
- **Limits** (`MessageQueue:Limits`):
  - `MaxQueues` (10000)
  - `MaxMessageBytes` (1 MB)
  - `MaxDequeueCount` (1000)
  - `MaxQueueLength` (unlimited)
- **Error messages**: only expected errors return their message. Unexpected exceptions return `Internal server error` and are logged.
- **Startup warnings** if authentication is disabled, `Authorization:Type` is unknown, or no HTTPS URL is configured.
- **Regex DoS**: queue patterns collapse multiple wildcards and use a match timeout.
- **Long polling**:
  - Polling no longer creates queues; a non-existent queue has hash code `0`.
  - Polling stops when the client disconnects.
  - Invalid `MaxRequestPollingSeconds` values no longer crash requests.
- **Confirm bound to user**: with authentication enabled, only the user that dequeued a message can confirm it (`confirmdequeue`). Without authentication nothing changes.

### Breaking Changes

- HTTP methods changed:
  - `dequeue` and `confirmdequeue`: `POST`
  - `remove` and `deletemessage`: `DELETE`
  - `register`: `PUT`
- Clients older than 4.0 (`MessageQueueNET.Client`) cannot use these endpoints anymore. Update the client library together with the server.
- Queue names starting with `_` or `-`, or containing `..`, or ending with `.` are invalid. Persisted queues with such names are skipped on startup (a warning is logged, the files are not deleted).
- `confirmdequeue` and `deletemessage` no longer create missing queues; they return an error instead.
- With authentication enabled, `/info`, `/openapi/v1.json` and `/scalar` require credentials.
- **Swagger UI replaced by Scalar**: the API description is generated by `Microsoft.AspNetCore.OpenApi` and is available at `/openapi/v1.json`; the UI is at `/scalar` (formerly `/swagger`).
  - The setting is now `openApiUI` (environment variable `OPENAPIUI`). `swaggerUI` still works as a fallback.
- **Docker images moved to GitHub Container Registry**:
  - `ghcr.io/jugstalt/messagequeue-net` (formerly `gstalt/messagequeue_net` on Docker Hub)
  - `ghcr.io/jugstalt/messagequeue-net-dashboard` (formerly `gstalt/messagequeue_net_dashboard`)
  - The images `aspnet:10.0-alpine` and run as the non-root user `app` on port `8080`. Persisted data belongs in `/home/app/messagequeue`.
  - `MessageQueueNET.Aspire.Hosting` uses the new images.
- `MessageQueueNET.Aspire` is no longer published as a NuGet package (deprecated).

### Build & Deployment

- Build, test, pack and publish with [Nuke](https://nuke.build) (`./build.ps1`, `./build.sh`); see the [build & release documentation](https://docs.gviewonline.com/other/messagequeue-net/release.html).
- One version for all packages and images, taken from the git tag `v*` ([MinVer](https://github.com/adamralph/minver)).
- Central package management (`Directory.Packages.props`), shared metadata in `Directory.Build.props` (SourceLink, symbol packages, README in the packages).
- One solution file `MessageQueueNET.slnx` (replaces `MessageQueueNET.sln` and `MessageQueueNET.Clients.sln`).
- GitHub Actions: CI for `master`, `v4` and pull requests; tags `v*` publish the NuGet packages (trusted publishing), the Docker images and a GitHub release.
- Release assets: ZIP packages for `win-x64` and (new) `linux-x64` with start scripts.
- The command line client is also available as .NET tool: `dotnet tool install -g MessageQueueNET.Cmd` (command `mqnet`).

### Fixes

- `ItemLifetimeSeconds` is calculated from the original creation date, also for messages that were re-enqueued after a missing confirmation.
  - The confirmation period starts at dequeue time; persisted unconfirmed items get a new `DequeuedUTC` field.
  - Items persisted by older versions fall back to the creation date.
- Thread safety of the queue operations (enqueue, dequeue, delete, clear).
- Expired messages are no longer returned or moved to the unconfirmed list on dequeue.
- `MaxQueueLength` is checked before messages are persisted.
- `register` waits until the queue properties are persisted and reports errors.
- `all`, `length` and `remove` report errors instead of returning an empty success result.
- The hash code of a single queue is calculated the same way as for queue lists (`LastModifiedUTC`).
- The background maintenance service no longer blocks threads (`.Result`) and stops immediately on shutdown; errors are logged instead of swallowed.
- Queues are restored asynchronously before the application starts; invalid queues are logged and skipped instead of stopping the restore.
- Removed the unused `Program_old.cs`.
- **No lost messages**:
  - `dequeue`: if the dequeue state cannot be persisted, the message is put back into the queue (and removed from the unconfirmed items) instead of being dropped. Messages already collected are still returned.
  - `enqueue` is all or nothing: if one message cannot be persisted, the already persisted ones are removed again and nothing is enqueued.
  - A queue removed by its `LifetimeSeconds` no longer swallows messages enqueued at the same moment (the queue is created again).
  - `QueuePersistNone.RemoveQueueItem` returned `false`; with `Persist:Type` `none` no message could be dequeued.
- `dequeue` on a queue with items that are removed in parallel no longer fails with an `InvalidOperationException`.
- `MaxQueues` is also enforced for parallel requests.
- Queue pattern matching: regexes are cached, queue names are collected without quadratic lookups.
- `QueuesService` logs errors instead of swallowing them. `RemoveQueue` returns whether the queue existed.
- `DequeuingClientsCount` and `DequeuingClients` return `0`/empty (instead of `null`) for queues with confirmation but no unconfirmed items; `null` only means that confirmation is not used.
- Client library (`MessageQueueNET.Client`):
  - Basic authentication credentials are encoded as UTF-8 (umlauts in passwords).
  - Queue names/patterns are URL-escaped.
  - Non-success responses throw `MessageQueueClientException` (derives from `Exception`) with the `StatusCode`.
  - All `IQueueClient` methods accept an optional `CancellationToken`.
  - Removed the dead certificate validation bypass in the `QueueClient` constructor.

### Documentation

- `dequeue` always creates a missing queue; the parameter `register` has no effect (documentation said the opposite).

### Tests

- New test project `test/MessageQueueNET.Tests` (xUnit + `WebApplicationFactory`). It covers queue name validation, path traversal, authentication, roles, HTTP methods, limits, and the enqueue/dequeue/confirm roundtrip.
